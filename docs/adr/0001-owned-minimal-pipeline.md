# ADR 0001：自有最小流水线，以官方行为为规范

- 日期：2026-09-10
- 状态：架构提案已落盘；用户已确认I20/R5与本机训练，行级数据语义仍待验证

## 背景

目标是用已有中国转债数据跑通价格图像 CNN 技术路线。官方代码与 CRSP、缓存和论文分析紧耦合；第三方虽简洁，但审计发现图像与切分行为有差异。

## 选择

自建一个 Python 包；从官方代码和论文提取可测试的行为规范，按模块独立实现。第三方提供接口组织参考，不整体 fork 后改造。初始单配置、单种子，产出可追溯的时间外预测；论文完整统计复现后置。

用户已选定 I20/R5；使用时间顺序验证而非论文训练期内随机70/30划分。因此应称“转债迁移基线”，不能声称所有实验设计与论文完全相同。

## 备选与权衡

| 路线 | 收益 | 成本/拒绝理由 |
|---|---|---|
| 直接改官方 | 与原流程近 | 引入美国数据、缓存、回归/组合环境，迁移范围大 |
| 直接改 Reed | 容易看到训练入口 | 继承不同图像、随机时间混合切分和训练状态问题 |
| 自有最小包（选择） | 数据边界与口径可控、可测试 | 需要自行写适配器/少量循环，并验证像素和参数细节 |

不用微服务、数据库服务或实验追踪服务；文件manifest足够首个闭环。可审计正确性优先于一次覆盖全部论文配置。

## 后果与重新评估条件

须维护迁移地图与像素验收样本；授权未明时不能复制源码。数据格式或算力发现不支持默认配置时更新ADR。正式对比论文时另开 paper-compatible 配置，不能覆盖本基线历史定义。

## G1数据政策决定（2026-09-11）

采用受限catalog离线研究基线：已验证存储格式与日历，原始数量物理单位及真实到达不作已知事实；日终可得是显式假设，不支持可交易性声明。详细政策集中在[architecture v1.1](../architecture.md)，依据、影响及双独立交叉审计PASS见[主控变更记录](../plans/2026-09-10-foundation.md)。未改变I20/R5目标，无既有实验需作废；若要求真实可得时点或原始单位，必须补充来源证据并重新审定受影响协议。
G2 v1.2已获用户批准：固定年度train/validation/test边界，原因与备选集中在architecture末节；两Agent独立及交叉审计后经用户确认生效，数据语义仍沿用v1.1。

G3实现沿用固定官方结构，独立实现不继承官方随机dummy构造的BN统计副作用；理由、审计及浮点限制见迁移地图G3节。数据/标签/切分不变。

G5正式实验提案（待用户批准）：全量固定G2样本、单seed、20epoch上限及资源/Test封存流程见architecture末节；双独立交叉审计支持提交确认。当前不替换生效协议，批准后才能配置正式运行。


## R2 paper-v1边界裁决记录（2026-09-17，PROPOSED / BLOCKED训练）

原CB发布main及G0–G8保持冻结，新分支独立复现论文。优先作者公开图像可节省原CRSP权限/渲染工程成本，但不等于原始OHLC管线复现，也不自动证明标签时间边界。

双独立审查及交叉质疑确认官方Ret_month按下一可用期间末记录计算；缺月时可能超出下一日历月。Date<2000-12-01仅为实现代理。决策：先完成1993–2000开发池来源/完整性/字段核验，若真实收益端点无法核验，训练入口BLOCKED；不把图像下一月记录当收益端点证明，不读OOS标签补证。

被否决的自动处理：盲用缺失收益作为负类；只提前数月截断并宣称无泄漏；擅改为固定20日收益；在未获裁决时默认接受官方边界风险。有限收益先过滤属必要数据修正，但精确样本政策及RNG仍需冻结，不在本轮建立最终训练名单。

后续可裁决入口：获得具有真实收益端点的同源合法数据；或用户明确批准另行忠实代码代理复现，并接受无法排除的边界污染限制。两者影响研究结论等级，不能由工程下载成功代替授权。P3资源、五成员seed和P4评价在启动前分别冻结；未决时无训练。


2026-09-17条件恢复后的裁决证据：下载/16个开发池文件核验成功，八年实际字段与完整schema元数据均无收益endpoint/原始期间序列；真实Ret_month端点不可可靠验证，跨OOS风险未排除、实际污染未证实。故训练继续BLOCKED。补证优先同源端点sidecar/原始序列；新增的条件性上界筛选仅在同源关系证实后才有边界保证，并改变样本/可能引入存续选择，不能把它当成已恢复原endpoint。完整A/B/C选项及结论等级见data-audit末节，尚无新协议获准执行。


B决策已获用户明确批准：接受官方Date代理未能排除的endpoint风险，冻结paper-b-v1，解除此前必须先取得A证据的协议阻断。保留已证实缺口与有限收益修正，不能宣称严格OOS无泄漏。双独立交叉审计确认受限P1契约及P2计划；P2完成后P3真实训练资源/恢复及P4评价仍是独立门禁，不因用户接受一种风险而解除全部门禁。


P3 Training Protocol于2026-09-18经用户要求与双审冻结：继承B/P2不变，新增固定五成员资源/确定性运行/完整epoch提交与恢复协议，版本paper-p3-training-v1。50epoch capped可作为预注册终态但必须披露；预算失败不算completed，不能按表现增尝试。当前只冻结计划，真实训练器和CUDA恢复尚未验收且用户未确认开训；完整条款在architecture，状态与审计入口在主控。
