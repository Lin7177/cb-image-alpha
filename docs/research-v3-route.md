# 后续研究路线（research-v3，DRAFT / 等待确认）

本路线基于 G0–P5 封存证据，目标是尽可能接近原论文，同时不把一次失败的 OOS 执行伪装成确认性结果。当前不启动任何实验。

## 仍有研究价值的约束

这些约束决定结论含义，应继续保留：P1/P2 数据与标签语义必须可追溯；`Ret_month` endpoint 未验证，不能宣称严格无泄漏；图像、标签、sample_id、归一化和 CNN 结构必须版本化；不使用未来信息；模型选择只能发生在开发数据；最终评估只能使用一次、预先冻结的未见数据；不以结果挑选子期、特征、阈值或成员；每次新读取必须有独立协议、监督账本和双 Agent 审计；P4 已读取的 OOS 永久视为已见，不能再次充当最终测试。

## 只是历史执行约束的事项

P4 的 7,200 秒墙钟、未实现的 supervisor、当次 8 GiB/磁盘预算和 P4 的 single-read run_id 是历史执行门禁。它们解释 P4 BLOCKED，不能被事后删除或放宽；若未来取得新数据并获批准，必须建立新协议、新预算、新 run_id，说明与 P4 的差异。P3 的训练参数、五成员、checkpoint 和结果仍冻结为复现证据，不因 P4 失败修改。

## 推荐路线

### R1：证据与路线关闭（当前，PASS 后停止）

问题：我们能否明确哪些结论已经成立？输入只读使用 G0–P5 receipts、主控和代码提交；禁止 OOS 内容、训练、调参、回测。交付 `docs/final-research-summary.md`、`final-evidence-index.json` 和本路线文档。PASS 条件是状态唯一、证据入口和限制清楚；若发现摘要冲突则 BLOCKED。结果是：基本流程完成；预测有效性未证实；P4 失败；当前 OOS 轴关闭。

### R2：端点与新未见数据可行性审计（用户确认后，零训练）

问题：能否取得合法、可追溯的真实收益端点和一段新的未见评估区间？只检查作者 sidecar/版本说明、授权数据或新的独立来源，不打开旧 P4 OOS，不用旧点估计指导选择。交付 endpoint lineage、数据成员 inventory、权限、成本和污染声明。预算建议：一次低成本审计，CPU/磁盘小于 30 分钟/1 GiB；若没有真实 endpoint 或新未见区间，PASS 仅表示可行性审计完成，立即 STOP，研究结论保持受限；不得用额外训练替代缺口。

### R3：新协议桥接评估（仅 R2 PASS 且用户批准）

问题：在新未见区间上，Date proxy 与真实 endpoint 是否导致不同结论，CNN 是否相对固定数值基线有增量？冻结单一主指标（pooled log loss，辅助 AUC/BA/Brier）、固定样本/阈值/模型、五成员或预注册单成员范围、一次读取边界和停止条件。先由双 Agent 审计，再建立 clean commit、supervisor、输入/代码/环境 hash、逐年排除账、预测和封存 manifest。任何输入映射、标签端点、资源或监督异常立即 BLOCKED；不重试、不按表现扩展。正结果只支持新数据/新端点下的有限证据，负结果则停止 CNN 优化轴；不开展收益回测。

### R4：结论归档（R3 完成后）

只整理差异矩阵：论文设定、官方代码、CB 项目实现、新端点版本和结果证据等级。R3 不通过则归档“工程流程完成、预测有效性未证实”；R3 通过也不能抹去 P4 失败或 endpoint 历史风险。该阶段不新增实验。

## 是否值得继续

推荐只继续 R2。它成本最低、能直接解决当前最重要的不可识别项；不推荐为了挽救 P4 点估计而再次读取旧 OOS。若 R2 找不到真实 endpoint 和新未见区间，建议关闭预测评价轴，把项目成果限定为可复现的图像 CNN 工程基线与方法迁移框架。

## 研究风险

旧 P4 指标已被观察，任何基于其选模型、挑年份或改阈值都会产生选择污染；Date proxy 的跨 OOS 风险仍未消除；新数据若权限或期间边界不清，只能作 development evidence；P4 工作树中的 `scripts/paper_p4_evaluate.py` 未提交，不能作为正式可复现实现。新协议和预算必须说明这些影响，不得把历史失败改写为成功。
